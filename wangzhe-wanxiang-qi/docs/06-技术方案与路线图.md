# 06 · 技术方案与路线图

## 6.1 技术架构总览

王者万象棋采用**「纯函数式游戏内核 + 可插拔表现层」**的分层架构，保证规则可测试、可复用、可跨端。

```
┌─────────────────────────────────────────────┐
│  表现层 Presentation                          │
│  Web(原型) / 移动端 / 桌面 / 小程序            │
│  - 渲染棋盘、动画、音效、交互输入               │
├─────────────────────────────────────────────┤
│  对局服务层 Match Service（正式版）            │
│  - 房间/匹配、天梯、回放存储、反作弊           │
│  - 权威服务器执行内核，客户端仅提交指令         │
├─────────────────────────────────────────────┤
│  游戏内核 Game Core（纯逻辑，跨端共享）         │
│  - 状态机：GameState + reduce(action)          │
│  - 规则：移动/攻击/技能/胜负/Buff              │
│  - 确定性：同样的初始态 + 指令序列 → 同样结果   │
├─────────────────────────────────────────────┤
│  AI 层 AI                                     │
│  - 规则 AI（原型）→ 搜索(Minimax/MCTS)→ 神经网络│
└─────────────────────────────────────────────┘
```

### 关键设计：确定性内核
- 内核是**纯函数**：`nextState = reduce(state, action)`，无副作用、无随机（或用可复现种子）。
- 好处：**天然可回放、可联网同步、可 AI 训练、可单元测试**。
- 原型已体现该思想：游戏状态集中管理，操作通过明确的动作函数改变状态。

## 6.2 原型技术栈（已实现）

| 层 | 选型 | 说明 |
| --- | --- | --- |
| 语言 | 原生 HTML / CSS / JavaScript | 零依赖、零构建，任意静态服务器可跑 |
| 渲染 | DOM 网格 + CSS | 9×9 格子、血条、高亮、日志面板 |
| 内核 | 纯 JS 状态对象 + 动作函数 | `game.js` 内 `state` + `move/attack/castSkill` |
| 英雄数据 | `heroes.js` 常量表 | 数值与技能与 `03/05` 文档一一对应 |
| AI | 贪心规则 AI | 优先攻击可击杀/最低血目标，否则向敌推进 |

> 选择「零依赖原生实现」是刻意的：让**方案可被任何人一键运行验证**，降低评审门槛。

## 6.3 正式版技术选型建议

| 模块 | 建议方案 | 理由 |
| --- | --- | --- |
| 游戏内核 | TypeScript（跨端共享 npm 包） | 强类型、可被 Web/RN/Node 复用 |
| Web 客户端 | React + PixiJS / Canvas | 复杂动画与特效性能佳 |
| 移动端 | React Native / Flutter / 原生 | 触屏体验与性能平衡 |
| 服务器 | Node.js(TS) / Go，WebSocket | 权威内核、低延迟指令同步 |
| 存储 | PostgreSQL + Redis | 账号/天梯/回放 + 匹配/在线态 |
| AI 训练 | Python + 自研内核绑定 | Self-play 生成数据，训练策略网络 |

## 6.4 里程碑路线图

### M0 · 概念验证（本项目当前阶段）✅
- 完整规则文档 + 可玩单机原型（棋盘/五英雄/回合/技能/AI/胜负）。
- 目标：**证明核心玩法成立且有趣**。

### M1 · 可玩性打磨
- 阵亡复活、双 Buff、草丛/河道地形、回合上限判定。
- 本地双人（Hot-seat）+ AI 难度分级。
- 内核抽取为独立 TS 包 + 单元测试覆盖规则。

### M2 · 内容扩充
- 英雄池扩至 15+，引入辅助/控制/召唤机制。
- 装备 / 金币 / 等级成长系统。
- 数值平衡：AI 自对弈跑胜率，收敛到 45%–55%。

### M3 · 联机与竞技
- 权威服务器 + 匹配 + 天梯 + 段位。
- 对局回放与分享、观战、解说位。
- 反作弊（服务器权威、指令校验）。

### M4 · 生态与商业化
- 赛事系统、创意工坊（自定义英雄/地图）、剧情战役 PVE。
- 异步对战（每日一步的「棋类外交」模式）。

## 6.5 商业化设计（非付费影响平衡）

- **红线：绝不 Pay-to-Win**，竞技对局所有英雄/数值公平可得。
- 变现方向：英雄皮肤、棋盘/棋子外观、动画特效、赛季通行证、观赛道具。
- 英雄可通过对局货币解锁，付费仅加速与外观。

## 6.6 风险与对策

| 风险 | 影响 | 对策 |
| --- | --- | --- |
| 玩法过于硬核，新手流失 | 拉新难 | 7×7 快棋 + 教学关 + AI 陪练 + 提示系统 |
| 平衡长期投入大 | 口碑波动 | 确定性内核 + AI 自对弈 + 数据驱动调参 |
| 回合制节奏偏慢 | 留存 | 回合计时器、快棋模式、异步对战承接慢节奏 |
| 与既有 IP 观感雷同 | 法律/辨识度 | 原创英雄与美术、原创世界观「万象大陆」 |
| 联网同步与作弊 | 竞技公平 | 服务器权威执行内核，客户端只发指令 |

## 6.7 成功衡量标准（北极星指标）

- **次日 / 7 日留存**：验证核心循环粘性。
- **平均每日对局数**：验证「可异步、想再来一局」。
- **英雄胜率离散度**：验证平衡健康。
- **对局完成率**：验证节奏与体验不劝退。
